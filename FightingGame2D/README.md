# Frame Fighters

CSVの全設定項目は [CSV設定項目一覧](public/data/CSV設定項目一覧.txt) を参照してください。

Google Chromeで動く、CPU対戦・トレーニング・オンライン対戦対応の2D格闘ゲームです。PixiJSが描画を担い、対戦ロジックは描画フレームから切り離した60Hz固定ステップで動作します。

## 設定と再利用

画面デザインを変えずにゲームの動作を調整する場合は、[gameConfig.ts](src/game/gameConfig.ts) を編集してください。ステージ・物理・入力猶予・ゲージ・ラウンド・演出・CPUテンプレート・初期キー配置を集約しています。キャラクター、技、コマンド、飛び道具は `public/data` のCSVで管理します。`engine.fixedFps` は決定論的同期の基準なので60から変更しないでください。

| 変更内容                                              | 編集場所                         |
| ----------------------------------------------------- | -------------------------------- |
| キャラクター・技・コマンド・飛び道具                  | `public/data/*.csv`              |
| 全キャラクター共通のルール・物理・CPU・演出・初期入力 | `src/game/gameConfig.ts`         |
| ポート・合言葉長・公開ホスト                          | `.env`（`.env.example`をコピー） |
| 判定アルゴリズムや画面構造そのもの                    | `src/game/*.ts`                  |

CSVと`gameConfig.ts`は起動時に値域・必須列・参照IDを検証します。不正値を暗黙の既定値へ置き換えないため、設定ミスは対戦開始前にファイル名・行・列を含むエラーとして確認できます。

合言葉による2人用通信は [modules/passphrase-room](modules/passphrase-room) に分離しています。別プロジェクトでは、このフォルダの `client.ts` と `server.mjs` を利用できます。詳細と最小実装例は [モジュールのREADME](modules/passphrase-room/README.md) を参照してください。

連番PNGを準備してキャラクター・アニメーション・技・コマンドを追加する手順は、外部公開用の[連番PNGキャラクター追加ガイド](docs/character-png-animation-guide-ja.md)を参照してください。

## 起動

```powershell
cd F:\FightingGame\FightingGame2D
npm install
npm run dev
```

表示されたURLをGoogle Chromeで開いてください。`file:///` で直接 `index.html` を開くのではなく、ViteなどのHTTPサーバー経由で起動します。製品ビルドは `npm run build` で `dist/` に生成されます。

別ブラウザ（同一PCまたはLAN上の別PC）で対戦する場合は、次でゲームサーバーとViteを同時に起動します。

```powershell
npm run multiplayer
```

ホストPCのWindowsファイアウォールでは、ブラウザが接続する`5173`の受信を許可し、対戦相手は `http://ホストPCのLAN-IP:5173` を開いてください。ルーム通信も同じURLの`/room`を経由するため、Viteの内部接続先である`ROOM_PORT`（既定8787）を外部公開する必要はありません。

公開環境の値はコードを変更せず、[.env.example](.env.example) を `.env` へコピーして設定できます。Viteとルームサーバーは`.env.local`およびモード別ファイルも同じ優先順で読みます。通常はdevelopmentモードを使い、別モードを両方へ適用する場合は起動前の環境変数`FIGHTING_GAME_ENV_MODE`へ同じモード名を設定します。`ROOM_PORT` はViteのWebSocketプロキシとルームサーバーの両方に反映され、`ROOM_MIN_PASSPHRASE_LENGTH` / `ROOM_MAX_PASSPHRASE_LENGTH` は画面とサーバーで同じ制約になります。ngrokなどの許可ホストは `FIGHTING_GAME_ALLOWED_HOSTS` にカンマ区切りで指定します。未指定時は `*.ngrok-free.dev` と `*.ngrok-free.app` を許可します。不正な数値は片側だけ既定値へ戻さず、両プロセスとも起動エラーにします。

## 操作

| プレイヤー操作                                                       | Xbox コントローラー                               |
| -------------------------------------------------------------------- | ------------------------------------------------- |
| 初期設定: `A / D` 移動、`W` ジャンプ、`F / G / H` 攻撃、`Space` 投げ | 左スティック/Dパッド、A=弱、X=強、B=必殺、RT=投げ |

ガードボタンはありません。敵と反対方向への入力で立ちガード、`下 + 敵と反対方向` の斜め後ろ入力でしゃがみガードになります。上段（`high`）は立ちガードのみ、下段（`low`）はしゃがみガードのみ、中段（`mid`）は両方で防げます。ガード成功時のダメージは0です。

一時停止メニューの「オプション」では、Player 1 / Player 2のキーボードとXboxゲームパッド割り当てを個別に変更できます。設定はこのブラウザに保存されます。`Esc` とXbox Homeは常にキャンセル用の固定入力で変更できず、キー設定中に入力すると変更を取り消します。

ローカル対戦ではPlayer 1を操作し、Player 2は選択したCPUレベルで動作します。オンライン対戦では両ブラウザともPlayer 1用に設定したキー配置、または1台目のXboxゲームパッドを使います。

波動拳は、向いている方向へ `↓` → `↓＋前` → `前＋必殺技` で発射します（初期設定の必殺技キーは `H`）。キャラクターは相手側へ自動で振り向くため、常に相手方向を「前」としてコマンドを入力してください。ジャンプ中は弱・強攻撃で空中攻撃を出せます。ジャンプ開始時の左右入力と空中入力には慣性が乗り、相手より十分高い位置では相手を飛び越えられます。

投げは moves.csv の range_x / range_y で設定した間合いで成立し、ガードを貫通します。方向キーなし／相手方向＋投げの前投げは、moves.csv の knockback_x / knockback_y で設定した量だけ相手を吹き飛ばします。後ろ方向＋投げは80%ダメージで位置を入れ替えます。発生10Fの間に相手も投げた場合は投げ抜けとなり、両者が後方へ弾かれダメージはありません。

対戦中に `Esc` を押すと、画面中央に一時停止メニューを開きます。一時停止メニューでは対戦を再開し、キーコンフィグでは前のメニューへ戻り、キー割り当て待機中は変更を取り消します。「Top画面へ」で対戦を終了してTop画面へ戻れます。

## カラー選択とVS画面

キャラクター決定後は、`デフォルト`・`黒系`・`赤系`・`黄色系`・`白系`からカラーを選択します。デフォルトは `characters.csv` の `primary_color` と `accent_color` を使用し、他の4色は全キャラクター共通の配色です。トレーニング以外で同じキャラクター・同じカラーになった場合は、P2（オンラインでは部屋に参加した側）を次のカラーへ自動変更します。

カラー確定後は約1.8秒間のVS画面を表示します。P1・P2のキャラクターと適用済みカラーを両端に表示し、中央の `VS` の後に対戦画面へ進みます。

## 対戦ルール

通常対戦は3ラウンド制・2ラウンド先取です。各ラウンドの開始時は画面中央に `ROUND n` を2秒間表示し、その後に対戦を開始します。画面上部中央には `ROUND n / 3` と99秒タイマーを表示します。時間切れでは残体力が多い側がラウンドを取得し、同値ならP1が取得します。トレーニングはラウンド制とタイマーを使わず、`∞` と表示します。KOになると1秒後に両者を開始位置・最大体力へ戻して再開します。

## ローカルCPU対戦

Top画面で「ローカル対戦」を選ぶと、キャラクター選択画面に `CPU LEVEL` が表示されます。レベルを選んでからキャラクターを決定してください。

- `0`: 何も操作しません。
- `1`: 接近して弱攻撃を行います。
- `2`: 接近・後ろ入力ガード・弱強攻撃を使います。
- `3`: キャラクター別の最適距離、飛び道具への防御、CSV定義のコマンド技を使う最強CPUです。

レベル1〜3の共通判断値は [gameConfig.ts](src/game/gameConfig.ts) の `cpu.levels`、レベル3のキャラクター別調整は `cpu.characters` で行います。`characters.csv` のキャラクターIDをキーに、距離・攻撃間隔・コマンド技のIDを追加・変更できます。コマンド入力列そのものは `moves.csv` と `commands.csv` から生成されるため、新しい技をCPUコードへ直書きする必要はありません。

## トレーニング設定

トレーニング中に `Esc` →「オプション」を開くと、P2ダミーの行動と練習表示を即時に変更できます。

- ガード種別: ガードしない／たちガード／しゃがみガード／攻撃ごとにランダムガード
- ジャンプ: 常にジャンプ／ランダムジャンプ／ジャンプしない
- 移動: 直立／前移動／後ろ移動／ランダム移動
- 攻撃: 攻撃しない／弱のみ／強のみ／技のみ／投げのみ／ランダム（CPU Lv3）
- 敵体力自動回復: OFF／ON。ONではP1がP2へ有効ダメージを与えた直後、P2の体力を最大まで回復します。
- 自キャラ必殺技ゲージ自動回復: OFF／ON。ONではP1がゲージを消費した直後に最大まで戻します。
- 入力履歴: OFF／ON。ONではP1の入力と継続フレームを左端へ表示します。
- 判定表示: OFF／ON。ONでは被弾判定を赤、攻撃判定を青の半透明矩形で表示します。

ランダム行動は固定フレーム番号から決めるため、同じ設定と入力列なら同じ挙動を再現します。

## オンライン対戦

画面右上の `ONLINE ROOM` から、既定では4〜32文字の合言葉で部屋を作成し、相手が同じ合言葉で「部屋に参加」を選ぶと対戦を開始します。文字数は`.env`の`ROOM_MIN_PASSPHRASE_LENGTH` / `ROOM_MAX_PASSPHRASE_LENGTH`で画面・サーバー同時に変更できます。オンライン中は両ブラウザともPlayer 1用に設定したキーボード操作、または1台目のXboxゲームパッドを使います。

対戦開始前に、両ブラウザのキャラクター能力・技・コマンド・飛び道具判定・決定論設定の指紋を比較します。不一致時は開始せず、両方へ再読み込みを案内します。対戦中に送受信するのはフレーム番号付きの入力ビットだけです。両者の同一フレーム入力が揃うまでシミュレーションを進めないロックステップ方式のため、同じ入力列から同じ試合状態を再現できます。ルームはメモリ上のみで、ホストまたは参加者が切断すると対戦を終了します。合言葉はLAN向けの簡易照合であり、公開インターネットでの秘匿用パスワードではありません。

## 実装要件

- 描画Tickerを最大60FPSに制限し、ゲームロジックは常に `1000 / 60ms` の固定ステップで実行します。
- 攻撃・必殺技・ジャンプは、行動可能になる5フレーム前の新規押下まで先行入力として保持します。
- ガードされていない技で `hitstun` が31F以上の場合、5Fのヒットストップと `data/sounds/slap-1.mp3` の打撃音を再生します。
- 各ステップの入力は読み取り専用のビットフラグとしてシミュレーションへ渡します。同じフレーム入力列なら同じ状態になるため、ロックステップ同期に利用できます。
- `public/data/characters.csv` がキャラクター、`public/data/moves.csv` が技の開始・持続・硬直・ダメージ・リーチ等を管理します。`max_health` と `damage` は同じ実数HPポイントです。たとえば `damage=500` は500ダメージとなり、割合換算は行いません。必殺技ゲージは最大100でラウンド開始時に満タン、対戦中は毎秒1ポイント回復します。`special_gauge_cost` は技ごとの消費量（0〜100）で、残量不足時はその技を発動・キャンセルできません。超必殺ゲージは最大300でラウンド開始時は0です。`super_gauge_gain` は技を開始した時点で加算される量（0〜300）で、最大値を超えません。`button` は `light`・`heavy`・`special`・`throw` を設定でき、`guard_bleak` は `true` でガードを貫通、`false` で通常のガード判定にします。`starter_proration` はコンボ始動時の補正率で、`20` は120%、`-10` は90%からコンボ減衰を開始します。キャラクター選択はCSVの2〜25体をそのまま表示し、少ないほどアイコンを大きく表示します。`characters.csv` の `icon_asset` には `public` 配下のPNGパス（例: `data/icons/hero.png`）を登録でき、未指定・読込失敗時は既定アイコンを表示します。`hurtbox_width / hurtbox_top / hurtbox_bottom` で本体に沿う被弾判定を調整できます。`moves.csv` の `use_state` は `ground`（地上）、`air`（空中）、`any`（両方）を指定できます。`attack_level` は `high`（立ちガードのみ可）・`mid`（立ち／しゃがみガード可）・`low`（しゃがみガードのみ可）を指定します。`projectiles.csv` の任意列 `hitbox_radius` で飛び道具ごとの命中判定半径を見た目と独立して調整でき、列または値を省略すると`gameConfig.ts`の共通値（既定14px）を使います。起動時にCSVを読み込み、列・値・参照IDを検証します。
- `blender_hero` と `stickMan` はプログラム描画の棒人間です。`crocodile_soldier` は `crocodile_soldier.json` のスプライトポーズを再生する、Blenderアニメーション対応キャラクターです。未使用の`blender_hero.json`はbones-v1の書式参照として残しており、現行キャラクターCSVからは読み込みません。

## 技中移動CSV

`moves.csv` の `range_y` と `knockback_x` の間にある `self_move_x` / `self_move_y` は、技を開始したキャラクター自身へ与える移動速度です。単位はピクセル/秒で、`self_move_x` の正値は前方、`self_move_y` の正値は上方向です。昇竜拳のような前進・上昇技には両方を設定します。`0` の場合は追加移動しません。

## 無敵フレームCSV

moves.csv の recovery の直後にある invincible_frames は、技を開始してから全攻撃（打撃・飛び道具・投げ）を受けないフレーム数です。0で無敵なしとなり、技の全体フレーム（startup + active + recovery）を超える値は設定できません。標準の昇竜拳には、上昇中をカバーする25Fを設定しています。

## ガード時CSV

moves.csv では hitstun の直後の guard_stun で、ガード成功側の硬直フレームを設定できます。さらに knockback_y の直後にある guard_knockback_x と guard_self_knockback_x で、ガード成功側とガードされた攻撃側をそれぞれ後方へ押す量を設定できます。3項目とも0を指定すると、対応する硬直・ノックバックは発生しません。飛び道具にも同じ設定が適用されます。

## コマンド技CSV

方向コマンドは [commands.csv](public/data/commands.csv) に定義し、[moves.csv](public/data/moves.csv) の `command_id` で参照します。`command_id` が空の技は、従来どおりボタンだけで発動します。複数の入力方式を許可する場合は `hadoken|hadoken_simple` のように `|` 区切りで複数IDを指定し、いずれかのコマンド成立で同じ技を発動できます。

| `commands.csv` 列 | 内容                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------- |
| `command_id`      | 技から参照する重複しないID                                                             |
| `sequence`        | `>` 区切りの方向入力順序                                                               |
| `max_frames`      | 通常は最初の方向、溜め技は後続方向から攻撃ボタンまでの猶予（60FPS固定フレーム）        |
| `priority`        | 同じ攻撃ボタンで複数コマンドが成立した場合の優先度（0〜100）                           |
| `charge_frames`   | 先頭の後ろ入力を維持する時間（前方向なしの途切れは合計4Fまで許容）。`0` は通常コマンド |

複数コマンドが同時に成立した時は、`priority` が大きい技を選びます。同値の場合は入力列が長い方、それも同値なら `moves.csv` の先行行を選ぶため、対戦同期でも結果が一定です。

`sequence` はテンキー表記で入力します。`5` はニュートラル、`6` は前、`4` は後ろ、`8` は上、`2` は下、`9`・`7`・`3`・`1` はそれぞれ斜め前上・斜め後上・斜め前下・斜め後下です。前後・斜め前後はキャラクターの現在の向きを基準に解釈されるため、自動振り向き後も同じCSV定義を使えます。`sequence` の最後の方向と同時、または最後の方向入力から6フレーム以内に、`moves.csv` の `button` を新たに押すと発動します。

`charge_frames` が1以上の行は溜めコマンドです。`sequence` の先頭を必ず `4` にし、その直後まで後ろ（`4`・`1`・`7`）を前入力なしで維持します。溜め区間ではニュートラル・上下入力など前方向を含まない途切れを合計4Fまで許容しますが、5F以上の途切れ、前入力、左右同時押しは不成立です。`max_frames` は溜め開始から消費せず、技ボタンを押したフレームから後続方向入力を逆算して照合します。したがって、`4>6,42,35,40` は40F以上後ろを維持した後に前＋技ボタンで発動でき、長く溜め続けても失敗しません。入力履歴は技の演出・硬直中にも記録されるため、前の技を出している間にも溜められます。被弾コンボ中の入力は従来どおり破棄されます。

```csv
command_id,sequence,max_frames,priority,charge_frames
hadoken,2>3>6,18,10,0
charge_shot,4>6,42,35,40
```

これらのIDを `moves.csv` の対応する技の `command_id` に設定します。未定義ID、重複ID、不正な方向名・溜め時間・猶予値は起動時に検出します。

## Blenderアニメーションの追加

Webブラウザーは `.blend` を直接再生できないため、同梱の [blender_export_fighting_animation.py](tools/blender_export_fighting_animation.py) でBlenderのArmature Actionを、ゲームがフレーム単位で再生できるJSONへ書き出します。

```powershell
blender --background Fighter.blend --python tools/blender_export_fighting_animation.py -- --armature Armature --output public/data/animations/my_fighter.json
```

Blender側では正面視点を `X=横、Z=縦` とし、Action名を `idle`、`walk`、`jump`、`light`、`heavy`、`special`、`hit`、`block`、`crouchBlock`、`ko` のいずれかにします。`moves.csv` の `animation` も同じ対応済み名を指定してください。書き出したパスを `characters.csv` の `animation_asset` 列に設定すると、骨格アニメーションが再生されます。

PNGを使うキャラクターでは、同じJSONに `sprite` を追加できます。`asset`、`scale`、`anchor`、`frameDuration` とアクションごとの `x / y / rotation / scale` ポーズを設定すると、透過PNGをBlenderアクションと同じ60FPS固定フレームで再生します。`crocodile_soldier.json` を編集例として参照してください。非デフォルト色の解析マスクは `gameConfig.ts` の `presentation.spriteColorMaskMaxDimension` を長辺上限として縮小し、VS画面中に先行生成します。
